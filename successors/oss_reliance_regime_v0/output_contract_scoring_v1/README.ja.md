# Output-contractの採点と模擬実行

[English](README.md) | 日本語 · [凍結済みの設計](../output_contract_probe_v1/README.ja.md)

この採点器は、凍結済みの96件の設計に従って保存済みの回答を採点します。Prompt、採点キー、parser、実行許可は変更していません。API clientは含まず、この96件をAPIで実測した結果もまだありません。

## 採点表の読み方

たとえば正答がAで、指示が `FINAL: A` の形式を求めているとします。

| 出力 | 正答 | 指定形式を遵守 | 両方を満たす |
|---|---|---|---|
| `FINAL: A` | はい | はい | はい |
| `A` | はい | いいえ | いいえ |
| `FINAL: B` | いいえ | はい | いいえ |
| `A because …` | いいえ | いいえ | いいえ |

記号だけを求めた場合、形式の判定は逆になります。AまたはBの一文字だけが指示どおりの回答です。親設計のparserは前後の空白だけを取り除きます。空文字や解釈できない回答も、すべての分母に残します。

[採点器](score.py)には、96件分の `query_id` と `output_text` だけをJSONL形式で渡します。行の順序は問いません。欠損・重複・予定外のIDや余分なfieldがあれば採点しません。凍結済み設計を照合したうえで、IDを使って回答と採点キーを結び付けます。採点が完了しても、回答の出所が証明されたわけではありません。

主な比較は「正答と指定形式の両方を満たさなかった割合」の **bare − marker** です。Full taskは各形式32件、mapping-onlyは各形式16件で別々に計算します。負の値なら、このpanelではbareのほうが両方を満たせなかった割合が低かったことを意味します。答えの誤り、形式違反、unresolvedの件数に加え、同じ親case・反復番号での形式間の差と、同じpromptの反復で答えや形式の分類が変わった件数も示します。反復では文字列そのものは比べません。内容は2種類を再利用しているので、96件を独立な標本とは数えません。

凍結済みの判定規則では、その割合が下がっても、読み取った答え自体の誤りが増えたならinterfaceの改善候補とはしません。差がない場合、条件によって結果が分かれた場合、悪化した場合もそのまま報告し、prompt探索には進みません。

## モデルを使わずに試す

Repositoryのrootから、Python 3.10以降で実行できます。

```sh
probe=successors/oss_reliance_regime_v0/output_contract_scoring_v1
run_dir=$(mktemp -d)
python3 -S "$probe/rehearse.py" --scenario mixed --out "$run_dir/mixed"
python3 -S "$probe/score.py" "$run_dir/mixed/observations.jsonl"
python3 -S -m unittest discover -s "$probe" -v
```

[模擬実行](rehearse.py)では、採点キーを使って人工的に回答を作ります。**モデルの観測結果ではありません。** 毎回新しいディレクトリにだけ記録します。

- `perfect`：模擬回答96件がすべて正答で、指定形式も守ります。
- `mixed`：正答は72/96件、形式遵守は60/96件、両方を満たすものは48/96件です。12件は解釈できません。両課題とも主な比較の差はゼロですが、対応する回答同士を比べると違いが残ります。
- `stopped`：12件目の結果を受け取れなかった状況を模擬します。最初の11件と停止記録を残し、終了コード2を返します。採点・再試行・再開はしません。

Receiptには観測ファイル、スコア（ある場合）、採点器・模擬実行のソース、凍結済みmanifestのhashを記録します。保存した模擬スコアには合成データだと明記します。鍵・provider接続・炉は不要です。予期しない異常終了や書き込みエラーで終了記録のないディレクトリが残ることはありますが、完了とは扱いません。

## 実測に進む条件

実測には、別途許可した実行計画、利用可否と料金の再確認、採点器と実行機の版の固定が必要です。上限は96回・USD 0.50のままです。再試行・モデル代替・自動再開は行いません。この実装だけでは、因果的な依存や機構の転移、APIの信頼性を検証したことにはなりません。
