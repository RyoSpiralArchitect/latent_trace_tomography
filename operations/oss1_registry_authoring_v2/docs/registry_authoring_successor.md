## Mandatory validation composition

A future post-training authoring bundle must pass these checks conjunctively,
in this order:

1. `validate_dependency_cluster_registry_v2(...)` runs the temporal successor
   plus every unchanged v1 registry semantic check.
2. `validate_controlled_anchor_plan_registry_binding(...)` binds the actual
   registry, lineage receipt, intake, and plan files; rejects duplicate JSON
   keys, non-regular registry/receipt paths, and caller/file divergence; returns
   their raw byte hashes; and then binds all nine planned runs, exact step/call
   counts, base artifacts and tokenizers, condition-specific targets, and
   descendant artifacts.
3. `load_source_evidence_catalog(...)` binds every v1 source envelope to one
   local typed payload, including raw bytes, canonical content, locator,
   chronology, and exactly-once inventory closure.
4. Kind-specific evidence-body semantic validators must derive and verify the
   registry claims represented by those payloads.
5. Only after all four pass may a separate concrete discovery authorization,
   authority-HMAC gate receipt, and frozen discovery-readiness check be built.

`validate_registry_authoring_bundle_v2(...)` composes steps 1 through 3 and
always returns:

```text
kind_specific_evidence_semantics_validated = false
discovery_authorization_ready = false
model_calls_authorized = false
```

The composed identity gate is therefore necessary but intentionally
insufficient. Neither the temporal validator nor the source catalog is a
substitute for the other. Even together they do not prove evidence-body truth,
provenance completeness, statistical independence, absence of abstract task
overlap, physical runtime isolation, or a latent mechanism.
