# どこまで確かめればtomographyと呼べるか

[English](tomography_readiness.md) | 日本語 · 2026年11月2日 · [判定項目の一覧（JSON）](tomography_readiness.json)

**今言えるのは、既知のOSS個体2組を新しい聞き方で区別し、あるAPIの未送信の回答候補を対照問題から絞れた、ということです。まだ言えないのは、介入で定義した量を、未知のモデル系列でも出力だけから測れる、ということです。** [今回の実験と再生](../reports/weak_projection_checkpoint_20261102/README.ja.md)が示したのは前者です。

### 何を測るのかを先に決める

観測する問いと読み取り方 **Q**、校正に使うOSS群 **C**、推定対象 **S**、そして用途に必要な分解能を明示します。今回の小さなcue測定では、元とdonorの回答が異なる対がある場合に限り、選択した箇所でのtargeted介入とmatched nullの転移件数差を、全16評価対で割りました。[凍結済みOSS-1](../protocols/oss_reliance_regime_v0/protocol.json)が定めるのは、3成分の介入感受性とsemantic側・cue側の差です。小さな測定の結果でこの契約を達成したことにはなりません。

Q上の観測がまったく同じなのにSが違う2個体があれば、その観測から別々の値を一意に返すことはできません。40問の衝突例では実測が9/16対12/16だったので、共通の点予測の最悪誤差は、この組だけでも3/32以上になります。これは**その有限の観測**についての限界で、あらゆる入力で2モデルの出力分布が同じだという主張ではありません。問いを変えて区別できれば観測法は前進します。そこから未知の系列でもSが測れるかは、別の試験です。

**呼び名の判定。** Qだけで成立するのは出力の監査です。「指名した対象における、Qに限定したOSS校正済みtomography」と呼ぶのは、因果参照の妥当性（R）、候補集合の実用的な分解能（I）、クラスタ全体を伏せたprofile転移（T）、事前に決めた未観測問題での比較（P）がそろってからです。一つでも欠ければ、実測した範囲に名前を戻します。未知例の帰属、確率、運用での更新警報には、さらにUの検証が必要です。再生可能な記録を公開したことは、その代わりにはなりません。

既存の[研究契約](research_contract.md)と[独立単位の定義](../protocols/oss_reliance_regime_v0/independent_unit_definition.json)が優先です。この整理で閾値は変更しません。

- OSS-1では、対象経路の介入効果とmatched nullの差は0.25以上、self-shamで元の回答を保つ率は0.90以上、対照箇所の効果の絶対値は0.10以下、codebook正答率は0.90以上です。探索seedを1つずつ除く8回のうち6回以上で同じ箇所が選ばれる必要があります。この箇所に条件付けた測定精度の区間は、モデル母集団の不確実性ではありません。
- 指名した個体での工学的試験では、依存クラスタを外した `delta_specific = S_semantic − S_cue` の平均絶対誤差は0.25以下が条件です。副次的なアンカー分類の条件はmacro AUROC 0.70以上、全foldで0.60超です。末尾1文字の正答率で達成したことにはなりません。
- [事前予測の採点](../protocols/oss_reliance_regime_v0/prospective_scoring_contract.json)では、**3分割すべての予測を固定してから**答えを開けます。候補方式と凍結済みの2比較法について別々に、クラスタを等重みにしてlog lossを平均します。候補方式は、**全体平均が良かった方**の比較法よりlossを10%以上減らす必要があります。foldごとに比較法を選び直したり棄権を除いたりしません。raw Brierと提示率は副指標で、確率較正の証明ではありません。
- 依存クラスタが3つなら、言えるのは**工学的な転移の試験**までです。確認的な主張には、新しいデータに対して検出力・許容リスク・多重比較の扱いを事前に決め、少なくとも開発用3クラスタと別に封印する確認用3クラスタを用意します。必要なら検出力に応じて増やします。promptや反復を増やしてもクラスタ数は増えません。

### 次の小実験：どの予測法が説明しているかを区別する

以下は**提案であって、凍結済みの実行計画でも実行許可でもありません**。観測用の対照では助言と正答を一致させます。新しい書類3枚・記号対応2種類で、今回と同じ3対照（完全一致、従来型の不一致、同じ接頭辞で末尾12文字が違う不一致）を2回ずつ出すと、別途許可された場合のAPI対照は36件です。**未送信の試験問題だけ**で、①コードを完全一致のまま助言をPASSからFAILにする、②同じ接頭辞の不一致のまま助言をFAILからPASSにする、という逆方向の2条件を使います。2反復なら試験問題は最大24件です。これらの衝突回答をOSS個体の選択には使いません。

1. 問い、学習データとの重複検査、記号対応、反復の扱い、完全一致の条件と全ケースを収集前に固定します。OSS側の試験問題の回答を記録しても、API側の試験問題は開けません。
2. APIの対照だけを見て、異なる2系列以上で安定して一致するOSS個体を同率も含めて残します。その候補群、全OSS、明文の規則、**対応する一致対照の回答のコピー**、助言に従うだけの規則について予測を固定します。**どの条件でどの比較法と予測が分かれるか**をAPIの試験問題を送る前に保存します。校正範囲外、またはどの単純な比較法とも1候補での予測が分かれなければ、棄権・判別不能を記録してそこで止めます。
3. たとえばコードが一致し助言だけがFAILなら、明文の規則と正しく答えた一致対照のコピーはPASS、助言だけを読む方式はFAILです。OSS候補がどちらを返すかは実測して固定するのであって、先にFAILと決めるわけではありません。計画した全条件を残し、比較法ごとに予測が分かれた条件での勝ち・負け・同点、両候補、反復不安定を、書類・記号対応別に数えます。助言だけの方式と同じ結果なら、助言のコピーは排除できません。

ここで差が出れば、新しい対象で盲検の挙動試験に進む理由になります。それだけでOSSの因果参照が妥当になったり、非公開モデルの回路が同定できたりはしません。

### 報告で使える言葉

- **今の証拠で言えること：**「このパネル・この時点のendpointでは、対照からOSS候補を絞ると、未送信6条件の回答を予測できました。2つの単純な比較法も同点でした。」
- **該当する条件を通った後に言えること：**「Qと校正群Cのもとで、対象は検証した分解能ではクラスRと整合します。提示率、誤差、未観測挙動の結果は以下のとおりです。」閉じたAPIでは、あくまで**条件付きの整合性**です。内部の事実と呼ぶには独立したベンダー側の検証が必要です。
- **含意しないこと：** 一意な内部trace・layer・chain of thoughtの復元、3系列からの母集団レベルの信頼性、ベンダー更新後も判断過程が同一であるという保証。
